# Hosted MCP capture adapter

The public API serves Streamable HTTP MCP at https://api.screenshotapi.tech/mcp using the official MCP SDK 1.31.0. Each request authenticates an active scoped account API key, applies request limits, validates Origin when present, and bounds request bodies to 256 KiB. The adapter delegates to the existing REST routes in-process, preserving ownership checks, durable submission idempotency, shared worker admission, and billing finalization. No browser runs in the MCP web process.

Tools: prepare_capture, take_screenshot, inspect_page, capture_element, get_capture_job, recover_capture_request. Preparation generates a stable retry key and estimates credits without charging. Captures return bounded metadata and artifact links, with asynchronous job handles. Inspection returns Markdown and accessibility text from the same render, bounded to 12,000 characters each and marked untrusted. Credentials are supplied by the client transport, never exposed as model-visible tool arguments.

The dashboard API keys page provides dedicated agent-key creation and copyable MCP connection settings. Mintlify and console guidance cover connection, retries, job tracking, credit policy, and revocation.

Verification: gateway regression suite includes official SDK HTTP client interoperability, discovery, estimates, durable capture replay, conflicts, account isolation, scopes, revocation, origin rejection, oversized bodies, rate limits, and existing REST billing behavior.

OAuth clients discover the Clerk production authorization server through public protected-resource metadata. Compatible clients onboard through CIMD with user consent and required S256 PKCE. Legacy DCR is disabled; older clients need a separately registered OAuth application. Clients request screenshot:write and jobs:read and include resource=https://api.screenshotapi.tech/mcp. Railway's capture-api requires the production CLERK_SECRET_KEY. Every OAuth request is verified with Clerk, rejecting revoked, expired, incorrectly scoped, or wrong-audience tokens. Billing and job ownership remain tied to the signed-in user and client.

Production Redis is private to Railway. The Vercel dashboard delegates submit, polling, and request recovery to the HTTPS API. These server requests bind the authenticated account, operation, request options, retry key, and timestamp with an HMAC derived from the existing capture-intent secret. Signatures expire after 30 seconds; submission replays use durable account-scoped idempotency. Public clients cannot supply a dashboard identity without a valid signature. The dashboard retains its existing preview and billing error responses. No Redis credential or public Redis port is required by Vercel.

Limitations: account-visible OAuth connection management, inline image slices, and an account-usage tool remain follow-up work. Existing local stdio is not the customer hosted connection. MCP cancellation does not cancel an already accepted durable capture or refund a successful capture. Local OAuth tests verify authentication and authorization behavior; a real client consent and refresh-token flow must also be verified after deployment.
