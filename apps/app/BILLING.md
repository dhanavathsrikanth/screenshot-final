## Payment integrity

Apply migrations `0007_glamorous_mister_sinister.sql` and `0008_tidy_leo.sql` before deploying this billing implementation. They add a per-payment prepaid ledger and a nonnegative refund debt field. Provider verification runs inside the serialized account transaction. A failed verification rolls back both the entitlement and its processed-event marker, allowing provider retries. Subscription events read the current Dodo subscription instead of trusting the event type to imply active status; old deliveries therefore cannot reactivate an expired subscription. Only an active subscription grants a paid allowance. Scheduled cancellation retains access while Dodo reports the subscription active; paused, held, past-due, failed, cancelled and expired subscriptions do not grant a paid plan. Current provider product, USD price, quantity, trial setting and checkout account metadata must match. Subscription ownership cannot transfer between accounts.

Successful prepaid payments require the exact purchased product, one unit, USD currency and advertised pre-tax amount. A payment ledger applies only the difference between the previous grant and the currently verified net grant, including proportional successful refunds. Failed and pending refunds grant no extra adjustment. Refunded credits already consumed or reserved become debt, which offsets future prepaid purchases; it does not remove monthly allowance. If a reserved capture subsequently fails, its returned credits also offset that debt. Subscription refunds follow Dodo's subscription lifecycle; issuing a refund alone is not an instruction to cancel recurring billing.

Checkout return parameters never directly grant benefits. Authenticated `/api/billing/verify` verifies the returned payment with Dodo and checks its checkout account metadata before applying the same idempotent billing handlers as the webhook. The billing page retries pending verification and refreshes the account afterward. The endpoint checks request origin and does not accept client-selected plans, amounts or user IDs.

Validation on 2026-10-11: seven price/payment validation tests, eight isolated database integrity tests, and local HTTP checks for invalid signature rejection and refusal to upgrade an unverified subscription. App and API TypeScript checks passed. These tests do not establish live payment acceptance or actual provider-to-deployed-app delivery. Dodo currently remains in test mode. Live launch requires live products and API credentials, a live signing secret and callback, and a completed payment/refund lifecycle test with a verified account.

Provider behavior reference: [Dodo webhook delivery, retries and ordering](https://docs.dodopayments.com/developer-resources/webhooks). Webhooks may arrive out of order and retry. Do not acknowledge processing failures as successful delivery or grant credits from the browser's claimed payment status.
